	- DevOps ::::
	
		DevOps is a Software Development Strategy/process, used to build collaboration between the teams like Development Team and Operations Team to achieve Continuous Development, Continuous Integration, Continuous Testing, Continuous Delivery, Continuous Deployment and Continuous Monitoring in more automated fashion.
		
		
		
	- How to Implement DevOps ?
	
		--> Identify the Teams involved :::
		
			- DevOps Team : (DevOps Architects/DevOps Consultants)
			
				- Infra-Structure Management Team --> 	# Create and Manage Infra-Structure
				- Application Development Team 		
				- Testing Team 	==> 					# 100 Test Servers 
				- Release Management Team 
				- Production Support Team 
				- Production Monitoring Team 
				- IT Security Team 


		--> Define Environments :::

				
			- Non-Prod Environments 						=========================>					Production Environment
			
			
				- Dev Environment
				
				- Build Environment --> (*.jar) --> Unit Test 
				
				- Test Environments 
				
					- QA 
					
					- UAT 									------------------------->						Production Servers (LIVE)
					
					
		--> Application Architecture :::

			- Monolith Application Architecture	
				- Tightly Coupled Application Architecture
				- All the Functions/Modules are tightly coupled
				- With this we can achieve Continuous Delivery. But, we cannot achieve Continuous Deployment.
		

			- Micro-Service Based Application Architecture
				- Loosely coupled Application Architecture
				- Here, each and every function / Module are called a Micro-Service
				- Each Micro-Service can be idependently developed, tested and implemented to production.
				- With this we can achieve Continuous Deployment

	- Stages of DevOps :::
	
	
			- Continuous Development :::
			
				- It is the capability of any Application Development Team to Continuously Develop code changes. 
				- It is a process that is used to improve the Developers' productivity.
			
				Role of any Developers ?
				
					- Understand the Requirement and Create the Source Code - Java/.Net/Python
			
				Manual Activities :::
				
					- Build the Source Code
						- Build is process of compiling the source code and create artifacts(Binaries: *.war.*.jar,*.exec,*.dll)
					- Perform Unit Testing 
					- Promote the Changes for further Testing Environments
					- Notify the Testing Team through emails

				Using DevOps Approach :
				
					Automate: 

						- Build the Source Code
							- Build is process of compiling the source code and create artifacts(Binaries: *.war.*.jar,*.exec,*.dll)
						- Perform Unit Testing 
						- Promote the Changes for further Testing Environments
						- Notify the Testing Team through emails
			
					- Create the Source Code - Java/.Net/Python
					- Save the Source Code in the Source Code Repositories(GitHub)			
			
				Tools :
				
					- IDE(Integrated Development Environment) --> Eclipse, Visual Studio, Visual Studion Code, Pycharm, IntelliJ
					- Build Tool & Unit Testing Tools ( Maven, TestNG,...)
					- Git, GitHub
			
		
		- Continuous Integration :::
		
				- It is the capability of any Application Development Team to Continuously Integrate the source code changes for further testing.		
		
				Automate: 

					- Build the Source Code
						- Build is process of compiling the source code and create artifacts(Binaries: *.war.*.jar,*.exec,*.dll)
					- Perform Unit Testing 
					- Promote the Changes for further Testing Environments
					- Notify the Testing Team through emails	
			
				Tools :
					- IDE(Integrated Development Environment) --> Eclipse, Visual Studio, Visual Studion Code, Pycharm, IntelliJ
					- Build Tool & Unit Testing Tools ( Maven, TestNG,...)
					- Git, GitHub
					- Docker, Ansible, Kubernetes
					- Jenkins
					
		
		- Continuous Testing :::
		
				- It is the capability of the Testing Team to Continuously Test the Changes 
				- Test Cases/Test Scenarios - Test Reports 
				
				Tools :
				
					- TestNG, Selenium
					- Jenkins 
					
					
		- Continuous Delivery/Deployment :::

			- Continuous Delivery ::
			
				-> Used to release the changes to Production Environment with manual approvals
				-> This process expect manual intervension/approval for production releases 
				-> During the process of application upgrade or downgrade, there might be application downtime
				-> This is used for Monolith Application Architecture
				
			Eg.: 
				--> Online Banking/Insurance/Logistic :::
				
					-->  Release Management Team :::
							Release Window 	==> 4 - 6 Hrs ==> Non-Business Hours
							
							StakeHolder ==> Release the Changes to Prod  V1 --> V2 
							
										==> Fix / Revert the changes 

									
			- Continuous Deployment ::
			
				- It is the process to release the changes to production environment, without any manual intervension/Approvals..
				- Never expects any manual approvals for Production Releases	
				- During the process of application upgrade or downgrade, there is no downtime
				- Zero Downtime can be achieved only with the Micro-Service based Application Architecture.
				- Is the matured level of DevOps.		
				- Shift Left Approach :::
				
					Dev----QA----UAT-----> prod 
				
			Eg.: 
				--> Facebook/Netflix/amazon.com/Gmail
